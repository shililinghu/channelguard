ChannelGuard 0.1.4 · 系统进程分流

【开启与后续添加】
在“应用接入”选中信道，添加 EXE 或从运行程序选择；需要游戏和后台服务一起接入时，添加具体安装目录。
“识别已安装应用”可勾选 QQ、微信、飞书、MiniMax Design、Steam、STOVE、MuMu、UU远程、雷神、夸克、明日方舟。
Steam 会读取现有游戏库目录；目录内后续安装的游戏自动匹配。新增另一个游戏库后重新识别或添加新目录。
点击“开启系统分流”，Windows 管理员提示由用户确认。仅驱动宿主提权，界面和网络内核保持原权限。
运行后新加 EXE / 修改分配自动应用，不用再往 ZoogVPN 逐个添加；双出口仍依赖之前排除的那一条直连内核。
添加 EXE 会匹配这个完整路径的所有实例，并尝试继承父程序信道。独立启动的服务、启动器退出后的游戏优先使用目录规则。
具体 EXE 优先于目录，较深目录优先。目录不能包含分流宿主或网络内核，也不能选磁盘、Windows、用户根目录。
已建立的 TCP / UDP 会话不会被迁移，重连或正常重启相关应用后再测。不要为测试强杀远程控制或聊天程序。
打开工具可恢复已保存的系统分流设置，并再次出现管理员提示；拒绝提示时不接管。没有安装开机服务。

【工作方式与实际验证】
使用 WinDivert 2.2.2-A 官方签名驱动截获可归属进程的连接；用户态中继经本地认证 SOCKS5 送入指定信道。
默认不处理未分配应用，不改系统默认路由、系统代理、系统时区，也不叠加 TUN。
支持 TCP 和 UDP。HTTP / SSH 上游不支持本版 UDP 接入，会明确拒绝；默认浏览器模式仍阻断非代理 UDP。
为两项中继端口 34010 / 34011 创建仅限本宿主程序的临时入站防火墙规则，正常退出清理。
启用前校验组件哈希；程序自身未代码签名，驱动使用上游签名版本。没有安装根证书、解密 HTTPS 或修改游戏进程。
“查看实际流量”显示内核观察到的进程、匹配规则、协议和目的地；规则加载不代表出口 IP 已实测。
已匹配应用在信道未运行、暂停、代理失效时阻断或连接失败，不自动改用另一条信道。

【必须理解的边界】
这不是独立 Kill Switch。驱动宿主退出、界面关闭或崩溃后，应用恢复系统网络；网络核心停止但宿主存活时匹配规则仍阻断。
PID 无法归属、共享系统 DNS 代查、虚拟机转发、其他加速器/VPN驱动流量，不保证逐应用匹配。
MuMu 后台程序目录可匹配，不等于已证明模拟器内所有游戏均经过此信道。需要模拟器内部出口实测。
父进程已经退出且缺少目录规则的独立子程序、跨目录服务、移动到其他路径的 EXE，需要另外添加。
普通浏览器的网络接管不改变时区、语言和定位权限；需要这些环境控制时使用工具启动的独立受管会话。
普通浏览器的 WebRTC UDP 由系统分流转发，但 WebRTC、DNS、IPv6 完整外部泄露审计仍需另外验证。
对未单独测试的应用和游戏不声称“零泄露”或全协议兼容。不绕过反作弊；有冲突应停止该应用的分流。
管理员直连阻断、旧版 TUN 与系统进程分流不能同时使用。

【本机数据】
规则和本地代理凭据保存在当前用户 DPAPI 加密控制文件中，界面定期发送心跳。
运行状态与最近连接元数据保存在本机 process-routing/status.json，不包含代理密码；不会上传。
检测会访问用户指定的公网 IP 检查站点，供其观察出口。检测记录中的公网 IP 属于历史结果，换网需重测。

第三方来源和修改说明见 THIRD_PARTY_NOTICES/PROCESS_ROUTER.txt；完整已修改中继源码及 WinDivert 源码随发行包提供。

【本机 VPN 兼容】
部分 VPN 的拆分驱动会改写被排除内核的 IPv4 UDP 监听。系统分流模式使用仅限 ::1 的内核监听，由界面内的 127.0.0.1 转接兼容 IPv4 客户端；不会把代理开放到局域网。网络内核和分流宿主有显式旁路规则，避免从已分流的启动器启动本工具时形成循环。
控制文件与状态文件支持 Windows 短暂读锁重试；辅助进程失联会显示错误，需要重新开启并确认实际流量。
Codex 软件包更新可能更换 WindowsApps 路径，更新后应重新选择当前程序及其 app 目录。
